## Задание 1. Шифрование бакета с помощью KMS

1. С помощью ключа в KMS необходимо зашифровать содержимое бакета:

 - создать ключ в KMS;
 - с помощью ключа зашифровать содержимое бакета, созданного ранее.

### Решение 1

Для выполнения задания использована инфраструктура Yandex Cloud, развёрнутая в предыдущей домашней работе.

С помощью Terraform создан симметричный ключ Yandex Key Management Service (KMS) со следующими параметрами:

- Имя ключа: `netology-security-key`
- Алгоритм: `AES_256`
- Период ротации: 8760 часов (365 дней)
- Статус: `ACTIVE`

Конфигурация ключа описана в файле `terraform/kms.tf`.

Для сервисной учётной записи, используемой при работе с Object Storage, назначена роль `kms.keys.encrypterDecrypter`, позволяющая выполнять операции шифрования и расшифрования с использованием созданного ключа.

Созданный ключ KMS:

![Созданный ключ KMS](img/image1.png)

Для существующего бакета `netology-myachmen-lb-20261017` в Terraform настроено шифрование объектов по умолчанию с использованием созданного ключа KMS.

Конфигурация шифрования добавлена в файл `terraform/storage.tf`:

```hcl
server_side_encryption_configuration {
  rule {
    apply_server_side_encryption_by_default {
      kms_master_key_id = yandex_kms_symmetric_key.homework.id
      sse_algorithm     = "aws:kms"
    }
  }
}
```

Поскольку настройка шифрования по умолчанию применяется к новым загрузкам объектов, ранее загруженный объект `mark-yachmen.png` был повторно загружен в бакет после настройки KMS.

До повторной загрузки проверка метаданных объекта не показывала использования серверного шифрования:

![Метаданные объекта до шифрования](img/image2.png)

После повторной загрузки выполнена проверка:

```bash
yc storage s3api head-object \
  --bucket netology-myachmen-lb-20261017 \
  --key mark-yachmen.png
```

В метаданных объекта присутствуют параметры:

```yaml
server_side_encryption: aws:kms
sse_kms_key_id: abj33bvkeutu1bdtlcu0
```

Это подтверждает, что объект зашифрован с использованием созданного ключа KMS.

![Метаданные зашифрованного объекта](img/image3.png)

Дополнительно выполнена проверка Terraform:

```bash
terraform plan
```

Результат:

```text
No changes. Your infrastructure matches the configuration.
```

**Результат:** создан ключ KMS, настроено серверное шифрование объектов в Object Storage и подтверждено фактическое шифрование файла с использованием созданного ключа.

## Задание 2*. Размещение статического сайта с использованием HTTPS

(Выполняется не в Terraform)* Создать статический сайт в Object Storage c собственным публичным адресом и сделать доступным по HTTPS:

 - создать сертификат;
 - создать статическую страницу в Object Storage и применить сертификат HTTPS;
 - в качестве результата предоставить скриншот на страницу с сертификатом в заголовке (замочек).

### Решение 2

Дополнительное задание выполнено через веб-консоль Yandex Cloud без использования Terraform.

Для размещения статического сайта создан отдельный бакет Object Storage:

`netology-myachmen-site-20261024`

При создании бакета выбраны следующие параметры:

- Класс хранилища: стандартное.
- Максимальный размер: 1 ГБ.
- Публичное чтение объектов: разрешено.
- Шифрование KMS: не используется.
- Версионирование: отключено.

Настройки создания бакета:

![Создание бакета для статического сайта](img/image4.png)

В разделе **Настройки → Веб-сайт** включён режим хостинга статического сайта.

Указаны файлы:

- `index.html` — главная страница;
- `error.html` — страница ошибки.

Настройки хостинга:

![Настройки статического хостинга](img/image5.png)

В корень бакета загружены HTML-файлы, подготовленные для домашней работы.

Исходные файлы сайта находятся в каталоге `site/` репозитория.

Сайт опубликован по адресу:

**https://netology-myachmen-site-20261024.website.yandexcloud.net**

Проверена доступность главной страницы через HTTPS:

![Статический сайт по HTTPS](img/image6.png)

### Проверка HTTPS-сертификата

Для сайта используется HTTPS-сертификат, предоставляемый инфраструктурой Yandex Cloud для стандартного адреса статического хостинга.

При проверке сертификата в браузере получены следующие сведения:

- Организация: `YANDEX LLC`.
- Центр сертификации: `GlobalSign RSA OV SSL CA 2018`.
- Срок действия: с 19 мая по 16 ноября 2026 года.
- Браузер подтверждает защищённое HTTPS-соединение.

![Проверка HTTPS-сертификата](img/image7.png)

Собственный сертификат через Certificate Manager не выпускался, поскольку сайт размещён на стандартном домене Yandex Cloud, для которого HTTPS обеспечивается облачной платформой.

### Проверка страницы ошибки

Для проверки обработки ошибок выполнен переход по несуществующему адресу:

https://netology-myachmen-site-20261024.website.yandexcloud.net/nonexistent-page.html

В результате отображается содержимое файла `error.html` с сообщением об ошибке 404 и ссылкой для возврата на главную страницу.

![Страница ошибки 404](img/image8.png)

**Результат:** статический сайт размещён в Yandex Object Storage, доступен по HTTPS на стандартном домене Yandex Cloud. Проверены защищённое соединение и отображение пользовательской страницы ошибки.
